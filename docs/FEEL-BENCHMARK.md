# 手感对标清单（FEEL-BENCHMARK）

> 来源：用户实机对比结论 —— **在 MuMu（Android 15）里玩官方构建的移动版后，判定「原版手感远好于本项目原型」**。
> 本文把这个结论拆成可执行项：左边是目前原型的数值，右边是差距与追赶方案。
> 凡是标 **[待实测]** 的，都需要在有 adb 的环境里量（方法写在最后）。

---

## 0. 结论

- 原版：GameMaker + YYC、987 对象 / 9,304 事件、**748 个 Draw 事件**、2,237 个精灵、194 房间（1280×720 ~ 8000×1500）。
- 原型：单文件 ~1,600 行、7 房间（480×270 单屏）、程序化美术、合成音频。
- **差距不是“有没有特效”，而是三层**：① 镜头与画幅 ② 帧动画密度 ③ 数值调校的细腻度。

## 2. 按 ROI 排序的差距项

### P0-1 镜头与画幅（最影响“像不像”）

| 原版 | 原型 |
|---|---|
| 房间 1280×720 ~ 8000×1500，**镜头跟随 + 前瞻 + 阻尼** | 480×270 固定单屏，无镜头 |
| 角色在屏幕上占比约 1/12 高 | 约 1/8 高（显得更“近”、信息量少） |

做法：逻辑分辨率提到 480×270 不变，但**房间宽度做成 960~1440**，加镜头（lateral deadzone + look-ahead 0.15s + 平滑）；垂直方向锁死（原作大部分横版房间不做纵向滚动）。

### P0-2 帧动画密度

| 原版 | 原型 |
|---|---|
| 跑 6–8 帧、挥刀 3–5 帧、受击 1 帧、死亡 3 帧 | 跑 2 帧，其余用特效 |

做法：至少补 **跑步 6 帧 + 挥刀 3 帧 + 受击 1 帧 + 死亡 3 帧**（24×40，锚点脚底）。这一步不改任何逻辑，只换绘制，收益最大。

### P1-1 死亡与重开的仪式感

原版死亡有明显演出（慢放/黑边/音效）后再重开，**重开间隔感觉约 1~1.5s**；原型是 0.35s 硬切，容易“没感觉”。

做法：把 `p.dead` 提到 0.8~1.2s，期间慢放 + 黑边 + 死亡姿势；重开用 0.2s 淡入。**[待实测：原版实测间隔]**

### P1-2 攻击的“重量”分级

原版不同命中（普通斩 / 处决 / 化劲反打）的顿帧与震动明显不同；原型只有连段分级。

做法：给“处决（处决帧）”“化劲反打”单独一套更重的 hitstop（12~18 帧）+ 更大的 zoom（1.12）+ 短慢放 0.1s。

### P1-3 触摸手感（移动端专属）

| 原版 | 原型 |
|---|---|
| 屏幕按钮 + 虚拟摇杆，按钮大、位置靠右下 | 网页版 6 个小按钮，尺寸 62px |

做法：按钮放大到 84~96px、间距 ≥16px，左下摇杆区 ≥ 屏幕 1/3；加“按住摇杆任意位置都能走”的浮动摇杆。

### P2-1 声音层次

原型：单层合成音。原版：刀风/命中材质/环境/音乐分层，且有空间感。

做法：命中按材质分两套（金属/肉体）；刀风随连段升调（已有）；加 0.15s 的短混响 tap。

### P2-2 场景纵深

已做 5 层视差（天幕/月/远山/楼群/街面道具），但建筑是程序化重复剪影；原版是手绘图块集 + 独立 alpha 层。

做法：出 3 张分层背景（960×540 透明 PNG）+ 1 套 16px 瓦片即可质变，见 `DESIGN-SPEC.md` 第 6 节接口。

## 3. 测量方法（给有 adb 的环境）

```bash
# 记录屏幕流
adb shell screenrecord /sdcard/f.mp4 --time-limit 20
adb pull /sdcard/f.mp4 .
# 逐帧比对（python + opencv）：
#  - 移动速度：按住方向键 1s，量角色 x 位移
#  - 跳跃高度/滞空：起跳帧到落地帧的帧数与最高点
#  - 死亡→重开：死亡帧到画面恢复可控的帧数
#  - 顿帧：命中瞬间画面静止的帧数（对比相邻帧像素差为 0）
```

| 死亡→可操作 | **[待实测]** | 0.35s |

## 4. 给下一个 Agent 的一句话

> 原版手感已经被用户实机验证为“明显更好”。优先做 **镜头跟随 + 帧动画密度**（P0），它们是感知差距的大头；数值微调放在其后，且先用第 3 节的方法量出原版数值再改，不要凭感觉调。
